# Acer One 8 T482L Kernel Porting Log

## Objective

Port a bootable kernel for the Acer One 8 T482L using a Linux 4.9 donor and stock boot/LK images as references. The active donor is Lenovo Akita MT6761; the earlier LibreHU AC8257 attempt is historical and was abandoned after compatibility failures.

## Initial baseline inventory: LibreHU trial (2026-10-29)

- Donor checkout: `LibreHU-main`, initial commit `aab700159`.
- Source tree is clean at checkout. It is a Linux 4.9.117 tree customized for an AutoChips AC8257/Jancar UJC201 car head unit; its board-specific drivers, DTS, and default configuration cannot be assumed to match the Acer.
- `/tmp/boot.img` exists and is 32 MiB. `file` identifies an Android boot image with kernel load address `0x40080000`, ramdisk load address `0x51b00000`, 2048-byte page size, and initial command line `bootopt=64S3,32N2,64N2 buildvariant=user`.
- `/tmp/lk.bin` exists and is 1 MiB. `/tmp/lk.img` does not exist.
- Filesystem has about 14 GiB available in the donor checkout and 3.1 GiB in `/tmp` at initial inspection.
- No source files have been modified and no build or flash has been performed yet.

## Work log

This chronological log covers both donor-tree attempts. Later entries supersede earlier status when the donor changed. It records evidence, source changes, build results, image hashes, and device tests; generated images and transient dumps remain outside the source tree.

## Kernel version and persistent logging audit (2026-10-29)

- Confirmed this tree is Linux `4.9.117`: top-level Makefile has `VERSION=4`, `PATCHLEVEL=9`, `SUBLEVEL=117`; the generated `out/acer_t482l/include/config/kernel.release` is `4.9.117+`. The tablet's `4.9.190+` report is from the TWRP recovery kernel.
- Found the original generated config had `CONFIG_PSTORE_RAM=y` but zero pstore memory/buffer sizes. `fs/pstore/ram.c:ramoops_register_dummy()` exits without registering a backend when `mem_size` is zero. The Acer defconfig now enables the TWRP-observed ramoops region at `0x47c90000` (size `0xe0000`), console `0x40000`, and pmsg `0x10000`.
- The source boot DTB has no `mediatek,ram_console` node. With the SRAM option, `ram_console_early_init()` returns if it cannot find that node, before using its configured fallback address. Changed Acer defconfig to the donor tree's DRAM ram-console path at `0x47c80000` (size `0x10000`), directly adjacent to the pstore region. This requires validation on-device; both addresses are static physical carveouts and the stock DTB does not describe them as reserved memory.
- At this point the generated `.config` confirms pstore settings, but the DRAM-path config change has not yet been rebuilt or device-tested. Previous pstore contents were shown to be stale and must not be treated as records from the latest test kernel.
- Build setup: added `build.sh` for the Acer defconfig and ARM64 `Image.gz`, defaulting to the available Android GCC 4.9 toolchain. Added host `-fcommon` for this legacy kernel's DTC build under modern host GCC. The Acer defconfig disables donor-only `ATC_AVIN`, which otherwise fails compilation on a `%d`/`ssize_t` format mismatch and is unrelated to the tablet.
- Metazone is required to satisfy references from donor camera, display, ION, and MMC code. Re-enabled it in the Acer config; because the Acer DTB lacks the Autochips node, its runtime initialization is expected to fail harmlessly, and this needs validation in boot logs. Fixed its opaque handle casts via `unsigned long` so ARM64 builds preserve pointer width before narrowing the driver's 32-bit context token.
- Fixed two ARM64 format warnings that were build blockers under the vendor's `-Werror`: ION's `size_t` heap size now uses `%#zx`, and camera ISP's `size_t` count uses `%zu`. The other format arguments retain their matching types; strict warnings remain enabled.
- The first strict rebuild then surfaced type/API mistakes in the new panel driver: this LCM API declares `struct LCM_UTIL_FUNCS` and `struct LCM_PARAMS`, and `<linux/delay.h>`'s function-like `mdelay` macro collides with the LCM util member name. Corrected the struct tags and explicitly undefined the Linux macro before calling the LCM callback.
- Fixed the next ARM64 `-Werror=format` failures in the framebuffer logs: `phys_addr_t` values now use `%pa` and pass their addresses, while the signed computed free-size is explicitly cast for hexadecimal output. These are diagnostics only; no framebuffer memory behavior changed.
- Guarded the display's optional fast-DMS branch on the index macro actually being defined; this donor revision references an undefined `METAZONE_FAST_DMS_INDEX` when its supposed `CONFIG_ATC_FASTDISP_VERSION` flag is absent from generated Kconfig.
- Restored `ATC_AOSP_ENHANCEMENT` because donor framebuffer ioctl types depend on it. Added Acer LCM hooks that report no Gaowin bridge and leave PWM backlight requests to the panel's existing DSI brightness callback. Guarded BCCT's optional high-voltage charger-manager calls on `CONFIG_MTK_CHARGER`; the Acer config disables that charger service, while its thermal/current-limit cooler remains built.
- Kept CMDQ's metazone header include path available independently of the enhancement flag; `cmdq_driver.c` still includes the shared header in this build, and the header itself is inert when the feature code is disabled.

- Verified the 204-record, 72-byte-stride Acer ILI9881C command table at raw stock-kernel `Image` file offset `0x01867780`: the 14,688 table bytes match the reference table byte-for-byte.
